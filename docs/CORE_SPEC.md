## How to read

One component is one group of functions of core.py. A tick is one occurrence of that component. Every requirement has the form "always satisfy" and does not depend on earlier ticks. Kind: SEC = security functional requirement (must hold), FUN = functional specification (what the code does). asis: ok = the original code already satisfies it, gap = the original violates it (a guard or a fix is needed). guard: pending = a requirement the original violates that the attach guards do not yet close (extension requirements that ask for behaviour the original lacks: call shape, content, order, budget, completion evidence).

Input = every value that the attacker is assumed to choose freely: LLM responses, instructions, the restored stream, results of tool code, time. The internal state of the Core (counters, ticket presence, current stage) is also an input. Output = the decisions and effects of the Core.

Integer constants are declared as FRET internal integer variables. ST_* = the nine TurnState values, ACT_* = action of the analysis LLM, DEC_* = decision of the evaluation LLM, GO_* = gate outcome, OP_* = history operation, IOP_* = instruction operation, LOP_* = LLM I/O operation, KIND_* = history entry kind, ROLE_* = LLM message role.

## Assumptions (to be guaranteed outside the Core)

- **A-01** The configuration (tools, agent_permissions, user_permissions, managed prompt, limits) is set by the operator and cannot be changed by the attacker.
- **A-02** Tool implementations (validate, resources, execute) are trusted code, and resources() computes honestly the resources that execute touches. The gate relies on this computation.
- **A-03** The user and assistant entries of a restored stream are authenticated by the frontend.
- **A-04** call_llm is an untrusted oracle. The Core makes no assumption about the content of LLM output (not even that it parses as JSON).
- **A-05** One TurnStages processes one turn at a time. The cancel callback is supplied by the frontend.
- **A-06** time.monotonic() is monotonic.
- **A-07** The Core has no notion of a principal. user_permissions must be the permissions of the authenticated user; the frontend guarantees this.
- **A-08** The call-order record and the usage totals are held in process memory. After a process restart or a history restore they start again from 0.
- **A-09** Cost limits are counted in characters (an approximation of tokens).
- **A-10** The content of the content policy and of the order rules (which tools and which orders are dangerous) is set by the operator. The argument shape check (GATE-17), the result size limit (EXE-16) and the cost limit (LLM-10) apply with defaults and need no rules.
- **A-11** The attach guards process one turn at a time in a process. The turn in progress, the usage and the context of the gate call are held in instance variables.
